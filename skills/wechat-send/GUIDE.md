# 微信发消息（截屏驱动）完整规范

不调用任何 IM 接口，直接操作桌面微信客户端（Weixin 4.x / WeChat 3.x）：找回窗口 → 搜索会话 → 核对标题 → 输入内容 → 点「发送」→ 截图验证。

适用：给指定群 / 个人发一条消息，且不想手动点。
不适用：读聊天记录做统计、批量群发、发文件图片。

---

## 0. 运行环境

| 项目 | 要求 |
| --- | --- |
| 系统 | Windows 10 / 11（脚本全是 Win32 API，macOS / Linux 不可用） |
| Python | 3.8+，**只用标准库**，不需要 pip install |
| 可选 | `opencv-python-headless` + `numpy`，仅 `cvfind.py` 需要 |

脚本目录就是本文件所在目录下的 `scripts/`。所有命令都在该目录下执行：

```bash
cd <本 skill 目录>/scripts
```

`python` 不在 PATH 时用 Windows 自带的启动器 `py`，两者等价：

```bash
py grab.py 微信 shot.png
```

## 1. 坐标系统（先理解这一段，后面全是它的应用）

**核心公式：屏幕坐标 = 截图内坐标 + origin。**

`grab.py` 只截目标窗口，并按窗口的可见边框（`DwmGetWindowAttribute`）算出 origin，所以：

- 窗口图宽度通常 ~1000px，**低于看图工具约 1092px 的缩放阈值**，图像按 1:1 显示，图上量到多少就是多少；
- 全屏图 1920 宽一定被缩放，目测值要乘约 1.758，这是历史上"点空"的头号原因。

实测对比（同一窗口）：

| 方式 | 耗时 | 体积 | 坐标是否需换算 |
| --- | --- | --- | --- |
| 全屏 GDI 截图 BMP | 1.9s | 7.9MB | 要，×1.758 |
| 窗口截图 PNG（本仓库 `grab.py`） | 0.25s | ~220KB | **不用** |

因此：**默认只截窗口**。只有需要看多个窗口的遮挡关系时，才 `grab.py full shot.png` 截整个虚拟桌面。

## 2. 五步流程

```bash
cd <本 skill 目录>/scripts

# 1) 确认客户端在跑，把窗口弄到前台
py win.py 微信

# 2) 截窗口图（打印 origin，后面所有坐标都加它）
py grab.py 微信 shot.png

# 3) 点搜索框 → 输入关键词（纯数字用 type.py，中文一律 paste.py）
py click.py <x> <y> --title 微信
py paste.py "宿舍群" --title 微信

# 4) 点搜索结果里的名字文字 → 截图核对右上角标题
py grab.py 微信 shot.png

# 5) 点输入框 → 输入内容 → 点「发送」→ 截图校验气泡
py paste.py "收到，我七点到" --title 微信
py click.py <send_x> <send_y> --title 微信
py grab.py 微信 after.png
```

`--title 微信` 是安全闸，不是可选装饰，见 §5。

## 3. 步骤细节

### 3.1 把窗口弄出来

| 情况 | 做法 |
| --- | --- |
| 没在运行 | `cmd //c start "" "<微信安装路径>\Weixin.exe"`，再 `py win.py 微信 --wait 20` |
| 在托盘里（进程有、窗口不可见） | `py win.py 微信` 会 `ShowWindow(9)` 恢复并置前，**不需要先判断可见性** |
| 停在头像登录页 | 点绿色「进入微信」，**别点「切换账号」**（会进账号选择）、**别点「仅传输文件」**（没有聊天列表） |

点「进入微信」之后主窗口会先隐藏着创建，屏幕上空白 1~3 秒是正常的，别当成失败；等 2 秒再 `py win.py 微信`。

进程名对照：新版 `Weixin.exe`，旧版 `WeChat.exe`；窗口标题都叫「微信」，标题里没有版本信息。

### 3.2 定位会话

搜索框在会话列表顶部。也可以直接按 `Ctrl+F` 聚焦搜索框，省一次点击（微信 4.x 实测支持）：

```bash
py key.py ctrl f
```

输入关键词的三种情况：

| 关键词 | 用什么 | 原因 |
| --- | --- | --- |
| 纯数字（如群号） | `py type.py 12345` | 数字不受输入法影响 |
| 含中文 / 标点 / 空格 / 表情 | `py paste.py "关键词" --title 微信` | **唯一稳妥方式** |
| 纯英文字母 | 也建议 `paste.py` | 中文输入法激活时，`type.py` 打字母会被当拼音，弹候选条，还可能遮住按钮 |

搜索框**输入后框内看不到字是正常的**（微信把查询移进搜索态，框里回显占位符）。判断输入成功看下面有没有出现分组：「群聊 / 聊天记录 / 收藏 …」。

命中结果里，**点名字文字，不要点头像**（头像会打开资料页）。同名的人会混在「聊天记录」分组，别点错。

### 3.3 进会话后必须核对标题

聊天区顶部标题是唯一可信证据：

- 群：`群名(6)`，**带括号人数**；
- 个人：只有昵称，没有括号。

标题不对就停，重新搜索，**不要在当前窗口里凑合发**。

### 3.4 输入与发送

点输入框内空白处（偏左上，避开下方图标行），然后：

```bash
py type.py 1                                    # 只有数字/字母时
py paste.py "收到，我七点到" --replace --title 微信   # 任意文本
```

- `--replace` 会先 `Ctrl+A` 再粘，用于清掉输入框里的旧草稿；
- 清空草稿也可以 `py key.py ctrl a` + `py key.py back`（`back` 比 `delete` 稳）；
- 发中文别再试 `type.py`：它只映射数字、字母、`-`、`.`，其它字符会被静默跳过，表现为"什么都没输入"。要用 `type.py --unicode "中文"` 也可以，它绕过输入法，但个别自绘控件不认，不如 `paste.py` 稳。

**发送按钮点，不要按 Enter**：微信的「Enter 发送 / Ctrl+Enter 发送」是可配置的，Enter 可能只是换行，消息留在框里等于白等。

### 3.5 收尾校验（不可跳过）

再截一张图，同时确认三件事：

1. 消息区右侧出现**绿色气泡**，内容与预期逐字一致；
2. 输入框清空，回到占位提示态；
3. 「发送」按钮变回灰色。

## 4. 更准的定位与校验

### 4.1 模板匹配（可选，需要 opencv + numpy）

肉眼在图上读数会有几像素误差；模板匹配给的是像素级中心，还附带一个可信度分数。

```bash
# 一次性：从截图里裁一个模板（换主题/DPI 后要重做）
py crop.py shot.png 872 972 62 30 tpl/my_button.png

# 之后每次：在实时窗口里找它，并点击
py cvfind.py --shot 微信 tpl/my_button.png --thr 0.85 --top 3
py cvfind.py --shot 微信 tpl/my_button.png --click --title 微信

# 想看框对不对：把匹配结果画出来
py cvfind.py --shot 微信 tpl/my_button.png --dump marked.png
```

要点：

- `TM_CCOEFF_NORMED` + 阈值 0.85，内部做 NMS 去重；
- 分数 1.000 表示像素级完全一致，通常说明模板就是从同一主题裁的；
- **换分辨率 / 换 DPI / 换主题 / 深浅色切换 → 模板失效**，重裁一次，或加 `--scales 0.9,1.0,1.1`；
- 有多个候选时必须看 `--top` 全部结果按坐标挑，别盲点第一个；
- 模板别裁太大：图标与固定文字（如「发送」）比动态内容区稳。

`tpl/example_button.png` 只是示例，**必须按自己机器的主题重做**。

### 4.2 像素差校验（纯标准库）

判断"点完这一下，到底变没变"：

```bash
py diff.py before.png after.png
py diff.py shot.png --rect1 860 970 90 40 --rect2 430 970 90 40
```

判读：`changed_pixels < 1%` → 大概没点中；`> 5%` → 确实切了状态。

## 5. 安全闸：`--title` 不是可选项

键击（`paste.py` 的 Ctrl+V）只会发给**当前前台窗口**，点击则会命中**最上层**窗口。两条都可能落到别的程序里。

实测事故：置前后下一条命令再点搜索框时，前台已被宿主程序抢回，点击落在它的全屏窗口上，随后粘贴把测试文字写进了它的输入框。

所以：

- `click.py --title 微信` 用 `WindowFromPoint` 判断"这一点会点到谁"，被盖住就先抢前台再测，仍不对就 **exit 3 不点击**；
- `paste.py --title 微信` 先抢前台并校验标题，不匹配就 **exit 3 不粘贴**；
- **abort 是保护，不是故障**：宁可没发出去，也不能发错窗口。

另外建议把「置前 → 点击 → 粘贴」串进同一条命令，减少前台被抢走的窗口期：

```bash
py win.py 微信 >/dev/null && sleep 0.4 && \
py click.py <x> <y> --title 微信 && sleep 0.6 && \
py paste.py "内容" --title 微信 && sleep 0.8 && \
py grab.py 微信 after.png
```

判断微信是否真的在前台，最终只认**最新截图里窗口是否完整可见**，不看 hwnd、不看 `IsWindowVisible`。

## 6. 常见坑

1. **托盘隐藏**：进程在、`IsWindowVisible=0`，`win.py 微信` 依然能找到（默认不过滤可见性）。
2. **点「进入微信」后界面消失**：隐藏创建，等 2 秒再找，不是失败。
3. **`type.py` 不认中文**：静默跳过，表现为没输入。
4. **输入法干扰**：中文态下打字母会被当拼音，用 `paste.py`。
5. **搜索框看着是空的**：正常，看下拉分组判断。
6. **搜索结果第一条未必是目标**：群聊、聊天记录、历史混排，点前核对，点后核对标题人数。
7. **「发送」灰着点不动**：输入框是空的，粘贴没生效，重新点输入框再粘，别连点。
8. **粘贴没覆盖旧内容**：加 `--replace`，或先 `key.py ctrl a`。
9. **窗口被盖住仍能截图**：`grab.py` 的 print 模式让窗口自己渲染，截到的是微信本体；但**点击和键击还是会打到上层窗口**，必须置前。
10. **print 模式偶尔截到重绘中的一帧**（半截图/空白区）：重截一次，或加 `--screen`（要求窗口在前台）。
11. **换机器必须重新量坐标**：分辨率、DPI 缩放、窗口大小、微信版本主题都会让坐标失效。

## 7. 安全约束（硬性）

- 发送前必须确认「发给谁 + 发什么」；只给了群名没给内容、或内容有歧义时，先问。
- 消息文本一字不改：不润色、不加表情、不加署名。
- 只发一处：不群发、不重发、不在标题未核对的会话里发。
- 宁可不发也不发错：任何一步认不准就重新截图，禁止盲点重试。
- 不替用户表态：涉及承诺、金额、时间、同意/拒绝的措辞，必须来自用户原话。
- 报告时说明：发到哪个会话（含人数）、发了什么、校验结果。

## 8. 脚本清单

| 脚本 | 用途 |
| --- | --- |
| `winutil.py` | 共用底层：找窗口 / 抢前台 / 命中测试 / DPI 感知 |

| `paste.py "文本" [--replace] [--title 片段]` | 剪贴板粘贴，中文唯一稳妥方式 |
| `type.py "文本"` / `type.py --unicode "文本"` | 逐字输入 / 绕过输入法注入 |
| `key.py ctrl a` / `key.py alt v` | 单键与组合键 |
| `diff.py a.png b.png` | 像素差对比，判断状态是否变了 |
| `cvfind.py` | 可选：模板匹配定位（需 opencv + numpy） |

## 9. 脱敏实测记录（仅供理解流程，坐标在本机无效）

一次真实发送（窗口 973×1037，origin 952,1）：

1. 客户端只在托盘 → `start` 启动 → 停在头像登录页 → 点「进入微信」→ 窗口消失约 2s → `win.py 微信` 恢复并置前；
2. `Ctrl+F` 聚焦搜索框 → `type.py 12345` → 下拉「群聊」第一条即目标群 → 点击名字；
3. 顶部标题核对为 `宿舍群(6)`，人数正确；
4. 点输入框 → `type.py 1` → 点「发送」；
5. 校验：右侧绿色气泡「1」、输入框清空、发送按钮变灰。✅

同场补充：同一窗口位置下，搜索框 / 输入框 / 发送按钮的相对偏移稳定；窗口换位置后必须全部重测。

工具选型结论：微信 4.x 是 Qt 自绘，**UIA（uiautomation / pywinauto）拿不到任何子控件**，别走这条路；可靠组合是「窗口级截图 + 1:1 坐标 + 命中测试 + 模板匹配」。
